# GPT 验收提示词

## 怎么用

1. 打开 ChatGPT，新建对话。
2. 把下面「提示词正文」整段复制粘贴进去。
3. 按 GPT 的要求，把文件内容贴给它，或者直接上传这几个文件：
   - `../index.html`（必须，2.5 千行左右）
   - `方案.md`（必须，规则依据）
   - `test.js`（建议）
   - `验收清单.md`、`自检报告.md`（建议）
4. 如果一次贴不下，先贴 `方案.md` 的 §5.1–§5.3 和 `../index.html` 里 `<script id="engine">` 那一整段（规则引擎），再让它先审规则；审完再贴 UI 段。

> 提示词本身不需要修改，直接用。

---

## 提示词正文（从这里开始复制）

```
你是德州扑克规则与前端代码的审查员。我要请你验收一个本地单文件德州扑克练习游戏，它按一份设计文档实现，我会把源码和文档贴给你。

【背景】
- 产品：本地离线、双击即玩的德州扑克练习工具，目的是帮初学者学会这个游戏怎么打。
- 形态：单个 HTML 文件，HTML/CSS/JS 内联，无外部依赖、无构建步骤、数据存 localStorage。
- 设计文档：`方案.md` v9。规则以它的 §5.1（数据结构）、§5.2（关键算法）、§5.3（测试用例）正文为准；文档末尾的「修订点」表是历史记录，里面可能有被推翻的旧说法，不要拿它当规则依据。
- 源码：`../index.html`，里面有两段脚本——`<script id="engine">` 是纯规则引擎（不碰 DOM），`<script id="ui">` 是界面与 AI。
- 自测：`test.js` 从 HTML 里抽取 engine 跑 104 条断言，当前全过；`check.js` 用 DOM 桩冒烟，单挑/6 人/9 人各打完 10 手；`开发工具/sixmax.js` 6 人桌 60 手随机压测。

【你要核查什么】
按下面五组逐项检查，**只读代码和文档，不要改写代码**，发现问题就指出来。

第一组：规则正确性（最重要）
1. 单挑：翻前是不是 BTN/SB 先行动、BB 后行动？翻后是不是 BB 先行动？
2. 6 人桌 / 9 人桌：翻前是不是从 UTG 开始顺时针？翻后是不是从按钮左侧第一位开始？
3. 最小加注额是不是「当前注 + 上一次完整加注额」？短全下（不足一个完整加注）是不是不更新这个值？
4. 多次短全下累计够一个完整加注额时，是不是按一次完整加注处理、并重新开放加注权？
5. 已经行动过的玩家，面对新的完整加注能不能重新加注？「本次完整加注的最后抬价者」是不是被正确排除？
6. 大盲选项（翻前全平跟到 BB 时 BB 可以过牌或加注）有没有实现？会不会被跳过？
7. 盲注不够时（短盲），是不是按法定盲注额计算当前注，而不是按实际投入？
8. 边池分层：每一层的人数是不是「含弃牌者」、可参与比牌的人是不是「只含未弃牌者」？
9. 边池归属：≥2 人比牌、恰好 1 人直接归他、0 人的层（死钱）怎么处理？守恒断言 `Σ 边池 + Σ 退款 === Σ 总投入` 成立吗？
10. 比牌：7 选 5 是不是覆盖了 C(7,5)=21 种组合？A2345 这种最小顺子有没有特判？
11. 奇数余数怎么分？是不是从按钮左侧第一位参与该池的玩家开始每人 1 单位？
12. 烧牌：底牌 → 烧 → 翻牌 3 张 → 烧 → 转牌 → 烧 → 河牌，烧牌有没有占 `deckState` 的位置？
13. 换街时，玩家级的 `facedRaiseAmount` / `actedBeforeLastFullRaise` / `reopenEligible` 有没有清零？`lastFullRaiseSize` 有没有重置为大盲？

第二组：教学系统
14. 每条复盘点评是不是都引用了对应动作的真实快照字段（比如 `potBefore`、`toCallBefore`）？有没有只凭最终输赢就下结论的情况？
15. 每条点评有没有注明假设（对手范围、底池赔率、有效筹码）？
16. 底池赔率的「所需胜率」算法是不是 `跟注额 ÷ (跟注前底池 + 跟注额)`？

第三组：数据与存储
17. localStorage 的 key 是不是 `poker.save.v2` / `poker.hands.v2` / `poker.notes.v2` / `poker.session.v2` / `poker.avatar.v1.<uuid>`？有没有把大图片重复写进每一手牌谱？
18. 牌谱 200 手上限、超了删最旧，实现了吗？
19. 旧数据缺字段时（`messages` / `sidePots` / `review` / `deckState`）有没有补默认值？导出再导入后牌谱和重放结果一致吗？
20. 头像：是不是先压到 64×64、单张不超过 8KB、超限拒绝并提示（不许静默失败）？导出是不是只带 `assetKey` 不带图片本体？

第四组：消息与 AI
21. 每条 AI 消息是不是都绑定了一个有效的 `actionIndex`？消息文本里会不会泄露底牌或牌力判断？
22. 关掉消息开关后，规则、AI 决策、牌谱、历史 `messages[]` 是不是都不变，只停止新消息生成和显示？
23. AI 三档的差异是不是只体现在「决策阈值、诈唬频率、对手模型」上？AI 有没有任何途径读到玩家底牌？

第五组：功能完整性
24. 对照 `方案.md` 第十章的六批迭代计划，逐项确认功能是否都在界面上可点到：规则引擎、牌谱重放、单挑、内置头像、行动消息、6 人桌、AI 三档、诈唬、消息开关、起手牌表、底池赔率、本地头像替换、复盘讲评、完整牌谱回放、教学消息联动、统计、笔记、自定义盲注、自定义玩家数（2/6/9 人）、牌谱导出导入。
25. 方案 §12「明确不做」的清单（在线对战、真钱、云同步、职业级 AI、手机适配、自由聊天、联网/语音消息）有没有被偷偷做了或漏掉说明？

【输出格式】
请按下面的结构回答：

一、总体结论
- 一句话判断：能不能验收通过（能 / 有条件通过 / 不能）
- 最严重的 3 个问题（如果有）

二、问题清单（按严重程度排序，每条包含）
- 严重程度：严重 / 中等 / 轻微
- 位置：文件名 + 函数名 或 方案章节号
- 问题描述：哪里不对、为什么不对
- 复现方式：怎么操作或跑哪个测试能看出来
- 建议改法：一两句话说清楚往哪个方向改

三、逐组核查表
- 第一组到第五组，每组的每一项标 ✅ / ❌ / ⚠️（不确定）并给一句理由

四、你没验证到的部分
- 明确说出哪些地方你没法从代码判断（比如需要实际跑起来才能确认的界面行为）

【注意】
- 不要重写代码，不要给我一整份改好的文件，只指出问题。
- 拿不准的地方标⚠️并说明为什么拿不准，不要猜。
- 如果发现文档和代码不一致，以文档 §5.1–§5.3 正文为准，代码是错的。
- 中文回答。
```

## 如果 GPT 说「内容太长装不下」

分三次发：

1. 第一次：只贴 `方案.md` 的 §5.1–§5.3，让它先读懂规则。
2. 第二次：贴 `../index.html` 里 `<script id="engine">` 整段，让它审规则引擎（第一组 1–13 题）。
3. 第三次：贴 `<script id="ui">` 整段 + `test.js`，让它审教学、存储、消息（第二到五组）。

每次开头都保留「背景」和「注意」两段，中间的问题清单只发对应组。
